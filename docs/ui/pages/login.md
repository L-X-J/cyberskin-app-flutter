## 页面区域

- 登录首页：Logo 宽 267，下面为三个宽 293、高 66 的正式 PNG 胶囊登录入口，底部为 14px、19px 行高、`#E4E4E4` 协议文案。
- 邮箱地址：左上返回按钮、`Your Email` 标题、宽度随内容列伸缩的 65 高胶囊输入、58 高 Next 按钮；只展示地址输入，发送成功后才切换独立验证码前景。
- 验证码：`6-digit code` 标题、实际发码邮箱、3+3 六格输入（基准单格 43 x 56，上限 43px 宽，窄屏仅缩小格宽）、重发倒计时、58 高 Sign in；不继续显示邮箱输入框或协议说明。文案采用 PRD 正确拼写 `Resend code`，不复现设计截图 `cod` 拼写错误。
- 背景：统一复用 `AppLottieBackground`；首页、邮箱地址、验证码由同一 `/login` 路由内的 `AnimatedSwitcher` 以 320ms 淡入和轻微位移切换，背景保持挂载。键盘只压缩前景，背景尺寸不变；退出步骤不再接受输入。系统减少动画设置下关闭前景切换动画。
- 协议：两种内容复用可点击文案，从 `/app/v1/config` 的 `agreements` 按 `tos` 和 `privacy_policy` 代码读取 HTTPS H5 地址；没有有效地址时不提供点击。

## 数据与状态

- 页面本地持有三个前景步骤和切换版本；输入写入 `LoginController` 并触发认证事件。各步骤拆分为独立文件，`login_page.dart` 只负责背景、动画和返回。
- `LoginController` 从 `ContentRepository` 读取启动配置和协议地址并调用平台 H5 打开器，页面不直接请求网络。
- 发码、校验、错误转换和会话跳转由 `LoginController` 负责。
- 首次发码成功固定 `verificationEmail` 并切换验证码步骤；发码失败保持邮箱步骤。验证码提交与重发均使用已确认邮箱，校验六位数字；返回邮箱清空验证码但保留邮箱。请求期间返回后到达的旧结果不允许重新打开验证码步骤。
- PRD 与接口约定的 60 秒重发冷却由截止时间计算；从后台恢复重新计算，Controller 关闭时销毁定时器；返回同一邮箱仍处于冷却时继续使用已发送验证码，不重复发码。过期、错误和限流消息由 Repository 结果展示，不在客户端假定验证码成功。

## 适配策略

- 内容最大宽度 402，宽屏居中；窄屏按可用宽度缩小按钮并保留滚动能力。
- 邮箱和验证码各自使用 `ListView`，低高度或键盘出现时提交按钮仍可滚动到达；返回顺序为验证码 -> 邮箱 -> 登录方式首页。
- 大字体由自然换行和内容增高处理，不锁定文字缩放。
- 邮箱地址与验证码步骤挂载后自动聚焦并弹出相应键盘；返回邮箱同样恢复输入焦点，退出步骤由页面壳排除焦点，背景保持挂载。
