# UI 视觉与适配验收规范

## 验收流程

每次 UI 任务按以下流程执行：读取规范和目标设计 -> 查找现有组件 -> 明确布局约定 -> 实现 -> 实际渲染 -> 对照修正 -> 记录验证和限制。

视觉验收不替代领域、Controller、协议或集成测试；它只验证用户可见的结构和行为结果。纯文档修改不需要为形式编写测试。

## A. 基准视觉验证

1. 使用页面布局约定指定的逻辑尺寸、平台、字体、文字缩放、安全区、固定数据和动画状态。
2. 使用真实 Flutter 渲染截图，而不是 Figma 导出、浏览器模拟 HTML 或手工拼图。
3. 对照页面结构、字体、行高、间距、素材比例、颜色、圆角、渐变、玻璃/模糊和交互状态。
4. 必要时使用叠加或差分图定位误差；系统状态栏、跨平台字体抗锯齿和非 App 系统区域单独判断。
5. 基准截图写入可追溯位置，并标明页面、Figma 节点、固定数据和代码版本。

不要用无依据的全局“像素误差百分比”替代人工设计核对。Golden 基线必须先经设计对照，Golden 只防回退，不能证明第一次实现已正确；不得自动更新 Golden 消除失败。

## B. 适配与行为验证

根据本次变更选取相关场景，至少覆盖：

| 场景 | 验收重点 |
| --- | --- |
| 窄屏和常见手机宽度 | 不横向溢出，核心操作可达，文本策略符合约定。 |
| 宽屏或横向窗口 | 内容列受控，布局按约定重排，不放大整页。 |
| 低可用高度 | 固定/悬浮区域不遮挡滚动内容。 |
| 系统大字体 | 正文不被自动缩小，文本能换行或推动布局。 |
| 长名称、多模式标签、空态与错误态 | 文本、卡片和操作不重叠，状态语义完整。 |
| 键盘弹出 | 输入、错误与提交操作仍可见可达。 |
| 窗口变化 | 设备状态、编辑内容、运行进度及必要滚动状态保持。 |

涉及自由控制时，还需验证布局重建不会重复启动设备、重复发送命令或重置运行状态。截图/Golden 使用 fixture 或 mock 状态，不能连接真实设备作为视觉验证副作用。

## 截图与测试产物

- 优先使用 Flutter widget/integration 环境可复现地产生截图；需要系统字体、键盘、真机渲染或 platform view 时使用对应设备/模拟器截图。
- 截图文件名包含页面、状态、逻辑尺寸和文本缩放，例如 `free_control_vertical_connected_402x949_text1.0.png`。
- 截图与 Golden 的保存路径由具体测试/CI 约定决定；本仓库目前没有已建立的视觉截图目录或 Golden 基线，新增首个 UI 视觉测试时在测试目录旁建立清晰的产物约定，并在页面布局约定中链接。
- 无法运行截图时，报告“静态实现完成，视觉待验收”，同时说明缺失的设备、平台或固定数据；若设计使用自定义字体而项目采用默认字体，记录字宽、行高或换行差异，不得把字体差异隐瞒为已完全一致。

## UI 任务交付格式

完成 UI 任务时，简明报告：

- 修改的页面或组件及对应 Figma 节点。
- 复用的已有组件或 token。
- 已执行的基准视觉和适配验证，及截图位置。
- 与设计或 PRD 的已知差异。
- 未验证或需要确认的内容。
