# UI 设计稿还原与响应式实现规范

## 目标

每项 UI 工作同时满足两种验收：

- **基准还原**：在页面布局约定指定的逻辑尺寸、平台、文字缩放、数据、动画和安全区条件下，与目标设计核对结构、字体、几何、素材和效果。
- **适配验收**：在其他可用空间、横向窗口、低高度、大字体、键盘、长内容与状态变化下，按页面约定换行、滚动、增高、裁切或重排，且功能完整。

设计稿是特定条件下的视觉结果，不是整页绝对定位或统一比例缩放的实现说明。

## 分层与数据

- `presentation` 只渲染页面、组件、局部交互和 GetX 状态；不拼接 BLE 帧、不发 HTTP、不写缓存规则。
- GetxController 只编排 UI 状态和领域用例。滑杆填充、档位高亮、百分比和展示文字必须由同一领域状态导出，不能保留设计稿中的静态示例位置。
- 设备能力、模块样式、模块排列和运行状态由 Repository/领域模型提供。控制页用明确的模块 renderer 映射已支持的类型和样式，不为每个设备复制整页。
- 新控制组合复用已有模块；新交互类型是否需要发版必须记录。后台一列/两列与窄屏、大字体下的降级关系没有 PRD 或布局约定时不得自行假定。
- 切换布局或因窗口变化重建 Widget 不得重启设备、重复下发指令、清除输入或重置运行/滚动状态。UI 截图和 rebuild 不得触发 BLE 操作。

## 布局与窗口约束

- 全部尺寸按 Flutter 逻辑像素理解。先确认 Figma 画板与导出倍率，不能把截图物理像素直接照搬。
- 常规间距、圆角、边框和图标采用已确认 token；卡片宽度、输入框和滑杆长度由父约束决定；文本与动态卡片按内容增高；图片和装饰以有限比例缩放并设置上下限。
- 用 `LayoutBuilder` 判断局部可用空间，用 `MediaQuery.sizeOf(context)` 获取窗口尺寸；其他媒介信息使用对应的 `MediaQuery` API。主要布局决策基于可用宽高和内容需求，不能按手机/平板型号或仅按横竖屏标签分支。
- 宽屏页面限制阅读或操作列最大宽度，并在有内容依据时转换为多列/并排区域。断点和最大宽度写入页面布局约定，官方示例值只能是候选起点，不是项目已确认数值。
- 不锁定方向，不以整页 `FittedBox`、`Transform.scale`、全局文字缩放限制或“当前宽度/设计稿宽度”乘法适配页面。局部装饰层可在明确边界内缩放或裁切。
- 使用 `SafeArea`、`Scaffold.resizeToAvoidBottomInset`、滚动容器和底部占位解决系统/键盘遮挡；先明确某一层是否已消费 inset，避免重复计算。
- 长画板高度不等于真实视口高度。固定区、滚动区、悬浮层和背景装饰必须在布局约定中分开；底部可达内容必须留出导航、pill、键盘和 safe area 空间。
- 窗口变化时保留控制状态、编辑内容、运行进度和必要滚动位置；仅根据新约束重排展示。

## 文字、素材与效果

- 先核对字体、字重、字号、行高、字间距和文本几何，再处理渐变、阴影、模糊与装饰。
- 大字体优先允许换行、增高、滚动或重排；不得自动缩小正文来保持原首屏。重要图标按钮需有可访问名称和合理触控面积。
- 当前项目统一使用 Flutter/Material 默认字体，不新增自定义字体依赖。若 Figma 使用其他字体，页面布局约定应记录字体差异及其对字宽、行高和换行的影响；除非 PRD 明确要求指定字体，不因字体差异阻塞实现。
- 正式图片、SVG 和图标进入项目素材流程，声明内容模式、原始比例、对齐和内部透明留白。不要用相似图标替换资源，也不要把含动态文案或交互的整张卡片切为图片。
- 使用 `BoxDecoration`、渐变、裁切、`BackdropFilter` 或自绘时，应先以截图校准 Flutter 实际效果；Figma 与 Flutter 同名的阴影、模糊或内阴影参数不保证视觉相同。不得用外阴影替代设计内阴影。
- 系统状态栏、时间、电量和灵动岛等 Figma 示意元素不由 App 自绘。

## Token 与组件

- `lib/core/theme/` 是稳定视觉 token 的代码归属。新增 token 必须有语义名、明确范围和至少两个稳定使用点，或由主题契约明确要求；文档只引用它，不复制易漂移数值。
- 跨业务域且稳定的基础交互、玻璃/渐变/光晕能力可放 `lib/core/`；业务语义组件放 feature 的 `presentation`；页面布局留在页面/feature 内。
- 优先复用现有组件。仅在语义、变化原因和所有权一致时抽象；同类组件用明确 `variant`、参数和状态表达差异，不创建万能 `utils`、JSON 页面引擎或单次使用的通用框架。
- 不将 Figma 返回的 React/CSS 逐行翻译。用 Flutter 正常流式布局表达页面，用局部 `Stack` 表达真实叠放关系。

## 任务流程

1. 阅读 [索引](README.md)、本规范、目标页面布局约定、PRD 和相关 Figma 节点。
2. 查找已有 theme、组件、素材、路由和状态模型，确认可复用边界。
3. 先补齐或更新页面布局约定，写明基准、数据、状态、约束和待确认项。
4. 按 `presentation -> domain <- data` 实现，避免把视觉工作带入业务/协议层。
5. 实际运行、截图并按 [视觉验收规范](visual-acceptance.md) 对照；修正后报告设计节点、截图位置、已验证项与限制。
