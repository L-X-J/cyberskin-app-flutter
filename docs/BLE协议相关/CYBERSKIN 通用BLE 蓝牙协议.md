# 元趣电动飞机杯通用BLE 蓝牙协议

本文档主要描述元趣电动飞机杯通用BLE 蓝牙协议，包括设备连接、通信协议等内容。
**注意**:文档中所有提到的整数，均为 10 进制整数。发送时需要转换为 16 进制。例如 10 进制整数 10 需要转换为 16 进制整数 0x0A。

> 版本信息

- **协议版本**：v1.0.8
- **最后更新**：2026-9-03
- **适用范围**：PechTak-xxx 系列飞机杯设备

## 设备信息

设备广播名称任意，但倾向于和设备型号相关，如：`PechTak-001`、`PechTak-002`等。
采用 Bluetooth Low Energy (BLE) 协议，广播数据中包含设备型号唯一标识码。  
**注意：**广播中需要在 `advertisementData` 中包含型号标识码，PechTak App 会通过扫描广播数据中的型号标识码来识别设备。

## 通信协议

###  通讯端口

> 上位机发送数据(飞机杯收指令)

- **服务（Service） UUID**：`ae30`
- **特征 (Characteristic) UUID**：`ae01`
- **属性 (Properties)**：`WRITE NO RESPONSE`

> 下位机上报数据(飞机杯上报数据)

- **服务（Service） UUID**：`ae30`
- **特征 (Characteristic) UUID**：`ae02`
- **属性 (Properties)**：`NOTIFY`


### 协议格式

#### 数据包结构

所有指令数据包遵循统一的格式规范：

| 字段 | 长度 | 说明 |
|------|------|------|
| 协议标识 | 1字节 | 上位机下发指令时固定为`0xAA`，上位机接收指令时候，固定为`0xDD`，表示协议开始 |
| 命令 | 1字节 | 具体功能命令码 |
| 数据0-N | 1字节 | 命令参数或数据，如果没有参数或数据该为就不存在，直接省略 |
| 校验 | 1字节 | 数据校验和 |

> 例如

```shell
发送： AA 55 FF
接收： DD 55 32
发送： AA 56 00
接收： DD 56 57 9A
```



#### 校验和计算（参考以下算法）

```c
static u8 make_data_crc(u8 *data, u32 date_len)
{
    u8 crc_value = 0;
    u8 crc_date_len = 0;
    u8 crc_data[16];
    
    memcpy(crc_data, data, date_len);
    crc_date_len = date_len;
    
    for(u8 i = 0; i < crc_date_len; i++)
    {
        crc_value += crc_data[i];
    }
    
    return crc_value;
}
```

#### 指令响应

当下位机接收到上位机发送的数据后，需要向上位机响应数据接收结果，如下示例：

如上位机发送：`AA 51 03 01 FF`

下位机需要返回：**`DD`**` 51 03 01 `**`32`**

> 说明

把除了协议标示（完整命令的第一位）和校验位（完整命令的最后一位），拿出来，按上面示例,下位机收到： `AA 51 03 01 FF`。

需要拿出 `51 03 01`, 然后在前面加上 固定协议标示：`DD`。

得出：`DD 51 03 01`

然后对这串数据做校验和（例如这段指令的校验和为：`0x32`），最后拼接好数据，上报给上位机：`DD 51 03 01 32`

## 元器件标识

元器件标识指的是 伸缩电机、振动电机、吮吸电机、加热功能的标识。

标识从` 0x01` 开始,以下是对应的标识码

- 伸缩电机：`0x01`
- 振动电机：`0x02`
- 吮吸电机：`0x03`
- 加热:`0x04`

## 上位机操控飞机杯的指令(0xAA)

### 设备关机 (0xAA55)

| 协议标示 | 命令 | 校验 | 说明 |
|----------|------|--------|--------|
| `0xAA` | `0x55` | `0xFD` | 设备关机 |

数据位 0 固定为 0x00。

> 例如：设备关机
```Hex
AA 55 FF
```
响应：`DD 55 32`

### 获取设备电量(0xAA56)

上位机在发送这个命令后，飞机杯需要根据上报电量数据百分比(0-100)。

| 协议标示 | 命令 | 校验 | 说明 |
|----------|------|--------|------|
| `0xAA` | `0x56` | `0x00` | 获取设备电量 |

> 例如：获取设备电量
```Hex
# 上位机发送
> AA 56 00
# 飞机杯回复(电量剩余87%)
< DD 56 57 9A
```
下位机（飞机杯）的响应参考下方表格

| 协议标示 | 命令   | 数据 0      | 校验       | 说明     |
| -------- | ------ | ----------- | ---------- | -------- |
| `0xDD`   | `0x56` | `0x00-0x64` | 计算校验和 | 电量上报 |

数据位 0 为电量剩余百分比，范围 0-100 之间的整数。 上报时候需要 10 进制转为 16 进制。
例如：

- 电量剩余 87%，需要转为 0x57

> 例如：电量剩余 87%

```Hex
DD 56 57 8A
```

### 控制元器件功率或工作状态(0xAA57)

该命令会控制当前某一个电机的运转功率，比如 电机1 运转功率 50%。电机2运转功率60%。

| 协议标示 | 命令   | 数据N     | 校验       | 说明                   |
| -------- | ------ | --------- | ---------- | ---------------------- |
| `0xAA`   | `0x57` | `01FF`... | 计算校验和 | 控制某个电机的运行功率 |

> 数据位 N 释义如下

每两个16机制字节为一组电机控制，分为标识位`[0]`和操作位`[1]`

标识位参考：[元器件标识](#元器件标识)

例如

- `01 FF`就是把 1 号电机 100%功率运行。
- `02 10`就是把2号电机16%功率运行。

#### 控制伸缩电机和震动电机

当当发送的标识位，对应的是伸缩电机、振动时，，操作位只会对应的是工占比（0-100%）

> 命令参考

如果设备存在多个电机但是只想控制一个电机 (1号伸缩16%功率运行)

``` text
AA 57 01 10 16
│  │  │  │  └─ 校验
│  │  │  └──── 操作位 0x10 = 16%
│  │  └─────── 标识位 01 = 伸缩电机
│  └────────── 命令 0x57
└───────────── 协议标识 0xAA
```

同时控制两个电机 （伸缩电机16% 功率、震动电机20%功率 ）

```
AA 57 01 10 02 14 28
│  │  │  │  │  │  └─ 校验
│  │  │  │  │  └──── 操作位 0x14 = 20%
│  │  │  │  └─────── 标识位 02 = 振动电机
│  │  │  └────────── 操作位 0x10 = 16%
│  │  └───────────── 标识位 01 = 伸缩电机
│  └──────────────── 命令 0x57
└─────────────────── 协议标识 0xAA
```

#### 吮吸功能控制

当发送的标识位，对应的是吮吸电机时候，操作位只会对应是哪个状态，如下
```
AA 57 03 01 05
      │  │  
      │  └─ 01 = 停止
			└──── 03 = 标识位 03 = 吮吸

AA 57 03 02 06
      │  │  
      │  └─ 02 = 开始吸气
			└──── 03 = 标识位 03 = 吮吸

AA 57 03 03 07
      │  │  
      │  └─ 03 = 开始排气（同停止，为兼容其他设备）
			└──── 03 = 标识位 03 = 吮吸
```

#### 加热功能控制

当发送的标识位，对应的是加热时，操作位对应的就是开启关闭加热功能。

`01` 为关闭加热，`02`为开启加热

对应命令如下示例：

```
AA 57 04 01 06
      │  │  
      │  └─ 01 = 关闭加热
			└──── 04 = 标识位 04 = 加热

AA 57 04 02 07
      │  │  
      │  └─ 02 = 开启加热
			└──── 04 = 标识位 04 = 加热
```

#### 数据示例

伸缩 10% ，震动 10%，吸吮 开始吸气， 加热开启

```
AA 57 01 0A 02 0A 03 02 04 02 23
      │  │  │  │  │  │  │  │  └─ 校验
      │  │  │  │  │  │  │  └──── 02 = 开启加热
      │  │  │  │  │  │  └─────── 标识位 04 = 加热
      │  │  │  │  │  └────────── 02 = 开始吸气
      │  │  │  │  └───────────── 标识位 03 = 吮吸
      │  │  │  └──────────────── 0x0A = 10%
      │  │  └─────────────────── 标识位 02 = 振动电机
      │  └────────────────────── 0x0A = 10%
      └───────────────────────── 标识位 01 = 伸缩电机
```

伸缩 40% 震动停止 吸吮排气

```
AA 57 01 28 02 00 03 03 36
      │  │  │  │  │  │  └─ 校验
      │  │  │  │  │  └──── 03 = 开始排气｜电机停止
      │  │  │  │  └─────── 标识位 03 = 吮吸
      │  │  │  └────────── 0x00 = 0%，停止
      │  │  └───────────── 标识位 02 = 振动电机
      │  └──────────────── 0x28 = 40%

```

吸吮停止

```

      │  │  └─ 校验
      │  └──── 01 = 停止
      └─────── 标识位 03 = 吮吸
```



### 模式控制（0xAA69）

| 协议标示 | 命令   | 数据N(两位一组) | 校验   | 说明 |
| -------- | ------ | --------------- | ------ | ---- |
| `0xAA`   | `0x69` | `01 F1`         | `0x01` |      |

以下为数据N释义：
两位一组

第一位：[元器件标识](#元器件标识)

第二位(关闭或开启指定模式)：

- 关闭模式：`00`
- 开启指定模式：`01`-`FF`

#### 数据示例

切换到伸缩电机 模式 1

```
发送：AA 69 01 01 15
答复：DD 69 01 01 48
         │  │  │  └─ 校验
         │  │  └──── 模式 1
         │  └─────── 元器件 01 = 伸缩电机
         └────────── 命令 0x69
```

伸缩电机 模式 2 振动电机 模式 1

```
发送：AA 69 01 02 02 01 19
答复：DD 69 01 02 02 01 4C
         │  │  │  │  └─ 校验
         │  │  │  └──── 模式 1
         │  │  └─────── 元器件 02 = 振动电机
         │  └────────── 模式 2
         └───────────── 元器件 01 = 伸缩电机
```

伸缩电机模式关闭 震动电机开启模式 2，吮吸开启模式 3

```
发送：AA 69 01 00 02 02 03 03 1E
答复：DD 69 01 00 02 02 03 03 51
         │  │  │  │  │  │  └─ 校验
         │  │  │  │  │  └──── 模式 3
         │  │  │  │  └─────── 元器件 03 = 吮吸
         │  │  │  └────────── 模式 2
         │  │  └───────────── 元器件 02 = 振动电机
         │  └──────────────── 模式 00 = 关闭
         └─────────────────── 元器件 01 = 伸缩电机
```



### 灯效控制（0xAA70）

在某些产品中，为了增加设备功能、增强可玩性，会引入 RGB 灯效。此时，为了进一步提升设备的可控性，我们在这里增加了上位机控制灯效的功能。

在灯效控制中，我们引入了一个**模式**的概念，例如模式 1 是跑马灯，模式 2 是呼吸灯。

为了减少控制的复杂度，我们将控制粒度只细化到特定模式下某颗灯珠的颜色和亮度。比如：设置模式 1 的第 1 颗灯珠，颜色为 ![](https://img.shields.io/badge/-FF69B4-FF69B4)，亮度为 50%。

| 协议标示 | 命令   | 数据5 位         | 校验   | 说明 |
| -------- | ------ | ---------------- | ------ | ---- |
| `0xAA`   | `0x70` | `12 FF 69 B4 32` | `0x01` |      |

> 数据位详解

**数据位示例 :** `12` `FF` `69` `B4` `32`

```
12 FF 69 B4 32
│  │  │  │  └─ Byte4 = 0x32  亮度 50%（有效范围 0x00–0x64，即 0–100%）
│  │  │  └──── Byte3 = 0xB4  B
│  │  └─────── Byte2 = 0x69  G
│  └────────── Byte1 = 0xFF  R
└───────────── Byte0 = 0x12
                 ├─ 高4位 0x1 = 模式
                 └─ 低4位 0x2 = 第 2 号灯珠
```

完整数据示例：

```
1. 模式一 1 号灯珠 颜色设为 3f7164 亮度为 100%
AA 70 11 3f 71 64 64 A3
2. 模式一 4 号灯珠 颜色为 b73f59 亮度 为 50%
AA 70 14 b7 3f 59 32 AF
3. 模式二 11 号灯珠 颜色为 #9eb887 亮度为 75%
AA 70 2B 9e b8 87 4b 6D
```



## 下位机（飞机杯）上报数据

### 下位机上报基础状态(0xDD00)

下位机需要每隔1秒上报当前运行状态，

包括

- 伸缩电机当前运行功率 `0x01`
- 震动马达当前运行功率 `0x02`
- 吮吸状态 `0x03`
- 加热状态 `0x04`
- 设备电量`0xC9`
- 是否正在充电 `0xCA`
- 是否关机（平时基本都为 `00`，但是在收到关机动作前，需要立即上报一次）`0xCB`

| 协议标示 | 命令  | 数据 N···   |  校验       | 说明 |
| -------- | ----- | -----------  | ---------- | ---- |
| `0xDD`   | `0x00  `   | 每两位代表一个功能状态 | 计算校验和 ||

#### 数据位N释义

每两位代表一个功能状态
例如 `02 10`就是表示 震动马达正在以 16% 的功率运行，

> 伸缩电机(`0x01`)和振动马达(`0x02`)

数据位 0 为当前电机运行功率(0%-100%)，正整数 0-100。
0 为电机未在运行 ，100 为电机满负荷运载。

数据示例：

- 伸缩电机未在工作（0%）：`01 00`

- 震动电机当前50% 功率运行：`02 32`
- 伸缩电机当前100%功率运行：`01 64`

> 吮吸(`0x03`)状态

吮吸基本只有三个状态

- 未在工作：`01`
- 正在吸气：`02`
- 正在放气：`03`

数据示例：

- 未在工作：`03 01`
- 正在吸气：`03 02`
- 正在放气：`03 03`

> 加热状态(`0x04`)

加热状态，包含以下两个状态

- 未在工作：`0x00`
- 正在工作：`0x01`

例如： `04 00`、`04 01`

> 设备电量(`0xC9`)

电池电量(0%-100%)，正整数 0-100。

数据示例：

- 电量剩余 30%： `C9 1E`
- 电量剩余 70%： `C9 46`
- 电量剩余 100%: `C9 64`



> 设备是否正在充电(`CA`)

前充电状态,目前只有两个

- 未在充电：` 00`
- 正在充电：` 01`

数据示例

- 未在充电：`CA 00`
- 正在充电：`CA 01`

> 关机状态(`0xCB`)

平时基本都为 `00`，但是在收到关机动作前，需要立即上报一。

数据示例：

- 未要关机：`CB 00`
- 马上要关机了：`CB 01`

### 下位机上报模式切换

具体命令同 [模式控制](#模式控制（0xAA69）) 中的数据示例答复



## 下位机上报自定义数据（0xDD01）

此指令，主要功能为，补充一些产品的需要上报的自定义数据，例如：元核，上报的晃动数据。
为了兼容产品后续的自定义上报，建议上报时候，携带 action 标记， 例如.

- `01`: 元核的晃动开关
- `02`: xx 设备用户的心率信息

| 协议标示 | 命令     | 数据 N···  | 校验       | 说明 |
| -------- | -------- | ---------- | ---------- | ---- |
| `0xDD`   | `0x01  ` | `01 00 30` | 计算校验和 |      |

例如元核设备上报振动数据：

```
DD 01 01 00 30 0F
DD 01 01 45 32 56
```
